[1.1] KIẾN TRÚC MANIM - 3 KHÁI NIỆM NỀN TẢNG
    • Mobjects (Mathematical Objects): Các khối xây dựng cơ bản - circles, 
      rectangles, text, graphs, functions. Là blueprint cần thêm vào scene 
      để hiển thị.
    • Animations: Định nghĩa transformations theo thời gian - fade, move, 
      rotate, morph.
    • Scenes: Container điều phối mọi thứ - objects xuất hiện thế nào, 
      animate ra sao, theo thứ tự nào.

[1.2] CẤU TRÚC CODE MANIM TỐI THIỂU
    from manim import *
    
    class SimpleScene(Scene):
        def construct(self):
            circle = Circle()
            circle.set_fill(BLUE, opacity=0.5)
            self.play(FadeIn(circle))
            self.wait(2)

[1.3] CÁC PHƯƠNG PHÁP CÀI ĐẶT MANIM
    • Local pip: Windows, Mac, Linux - cần quản lý dependencies
    • Conda: Môi trường isolated, tránh xung đột versions
    • Docker: Đảm bảo consistency across machines
    • Replit: Cloud-based, không cần cài đặt, làm việc trực tiếp trên browser

PHẦN 2: LỜI KHUYÊN TỐI ƯU HIỆU SUẤT
================================================================================

[2.1] TỐI ƯU WEB ANIMATIONS (JavaScript/CSS)
    • Sử dụng requestAnimationFrame() để đồng bộ với refresh rate browser
    • Batch read/write operations trên DOM để giảm reflows và repaints
    • Animate CSS transforms và opacity (được GPU tối ưu) thay vì 
      width, height, margin, padding
    • Sử dụng will-change và translate3d(0,0,0) để kích hoạt hardware 
      acceleration

[2.2] TỐI ƯU MANIM
    • Chia animation dài thành các sections modular
    • Dùng skip_animations=True trong development, chỉ render section 
      đang chỉnh sửa
    • Render full chỉ trong production cuối cùng

[2.3] TỐI ƯU LARGE DATASETS
    • Matplotlib: Sử dụng rasterization cho massive point clouds
    • Plotly: Data aggregation, downsampling, hoặc webGL rendering

[2.4] FRAME RATE TARGET
    • Smooth animation = 60 FPS = ~16.7ms per frame
    • Animation dưới 300ms cảm giác responsive
    • Animation chậm hơn nên phục vụ mục đích narrative cụ thể

    • KHÔNG render toàn bộ sequence mỗi lần sửa
    • Tạm disable non-essential animations bằng comments hoặc conditional logic
    • Chỉ render section đang develop để tăng tốc feedback cycles

[4.3] TEST ON TARGET DEVICES
    • Performance khác nhau giữa các hardware
    • Test web animations trên slow devices và browsers
    • Identify bottlenecks trước khi deploy

[4.4] LEVERAGE EXISTING SOLUTIONS
    • Explore library docs và community examples TRƯỚC KHI viết custom code
    • Hầu hết animation patterns phổ biến đã có sẵn built-in hoặc 
      community-shared

[4.5] PERFORMANCE PROFILING
    • Dùng browser developer tools
    • Dùng Manim's logging để identify animation tốn resources
    • Targeted optimization > speculative improvements

[4.6] MOTION DESIGN PRINCIPLES
    • Sử dụng easing functions (acceleration/deceleration)
    • Tôn trọng timing constraints

    • > 300ms = cần mục đích narrative rõ ràng

PHẦN 9: KỸ THUẬT VECTOR VÀ LATEX
================================================================================

[9.1] VMOBJECTS - VECTOR GRAPHICS
    • Định nghĩa shapes bằng Bézier curves → scaling vô hạn không bị pixelation
    • Data structure: List of anchor points + handles xác định curvature
    • Boolean Operations: Union, Intersection, Difference, Exclusion
    • Ứng dụng: Xây dựng geometries phức tạp từ primitives đơn giản

[9.2] LATEX INTEGRATION WORKFLOW
    Cơ chế hoạt động:
    1. Tex object instantiated → Manim tạo file .tex
    2. Compile bằng TeX distribution (TeX Live/MiKTeX) → DVI file
    3. Convert DVI → SVG bằng dvisvgm
    4. Parse SVG → VMobject

    Performance bottleneck: 
    • LaTeX compilation là I/O heavy, thường là phần chậm nhất
    • Manim dùng hashing + caching - nếu LaTeX string không đổi, reuse SVG cũ

    Customization:
    • Dùng TexTemplate class để thêm packages (physics, amssymb)
    • Method: add_to_preamble() để inject dependencies

PHẦN 10: ANIMATION LIFECYCLE VÀ PATTERNS

[10.1] CẤU TRÚC CƠ BẢN
    • construct() method trong Scene class = main timeline
    • self.play(Animation) = unit of action cơ bản
    • Manim tính interpolation giữa start và end states theo run_time

[10.2] MODERN .animate SYNTAX
    # Declarative style - tự động tạo Target mobject
    self.play(square.animate.shift(RIGHT))
    self.play(circle.animate.scale(2).set_color(RED))

[10.3] UPDATERS - CONTINUOUS FRAME-BY-FRAME LOGIC
    # Label luôn stay above moving box
    label.add_updater(lambda m: m.next_to(target, UP))
    
    Đặc điểm:
    • Lambda function execute mỗi frame render
    • Enforce geometric constraints bất kể target move thế nào
    • Tạo simulation-like environment thay vì rigid keyframe system

PHẦN 11: WEB-NATIVE TOOLS - MOTION CANVAS & REMOTION
================================================================================

[11.1] MOTION CANVAS (TypeScript)
    
    Kiến trúc:
    • Render bằng HTML5 Canvas API (không phải DOM)
    • Tối ưu cho high-performance vector graphics
    
    Generator Pattern:
    • Dùng function* và yield keyword
    • yield* rect().opacity(1, 1); → animate opacity lên 1 trong 1 giây
    • yield* all(...) → chạy nhiều animations đồng thời (concurrency)
    • Procedural style trực quan hơn cho linear storytelling
    
    Signals Architecture (giống SolidJS):
    • Signal = value tự động update dependencies khi thay đổi
    • Ví dụ: Circle radius là signal, line length phụ thuộc radius
      → Animate radius = tự động animate line length
    
    Visual Editor:
    • Split-screen: code bên trái, real-time preview bên phải
    • Interactive scrubber: inspect object properties tại bất kỳ frame nào
    • Feedback loop nhanh hơn nhiều so với Manim's compile-render-view

[11.2] REMOTION (React/TypeScript)
    
    Kiến trúc:
    • Treat video frame như React component tree
    • Render HTML/CSS elements (dùng Flexbox, Grid, SVG)
    • Export: Headless browser (Puppeteer) screenshot từng frame → FFmpeg stitch
    
    Ưu điểm:
    • Import bất kỳ npm library: D3.js charts, Lottie animations
    • Ideal cho data-driven videos với existing JS visualization libraries
    
    Licensing:
    • Free cho individuals và teams ≤ 3 người
    • Commercial license required cho larger companies

PHẦN 12: SCIENTIFIC VISUALIZATION TOOLS
================================================================================

[12.1] PLOTLY - FRAMES FRAMEWORK
    • Xây animations bằng frames: base figure + sequence of frame objects
    • Interactivity mặc định: zoom, pan, hover trong khi animation chạy
    • animation_frame argument trong px.scatter/px.bar
    • Custom controls: updatemenus để tạo play/pause/speed buttons

[12.2] MODERNGL - SHADER-BASED ART
    Khi nào dùng: Hit performance limits của CPU-based rendering
    
    Concepts:
    • VBOs (Vertex Buffer Objects): Pack vertices, colors vào numpy arrays
    • VAOs (Vertex Array Objects): Gửi data lên GPU
    • Custom GLSL shaders cho vertex và fragment stages
    
    Ứng dụng:
    • Per-pixel operations: Mandelbrot set, fluid dynamics
    • Generative art: Millions of particles at 60 FPS
    • Không thể làm được trong Manim's Python loop

[12.3] VPYTHON - PHYSICS SIMULATION
    Syntax:
    while True:
        rate(60)
        ball.pos += ball.velocity * dt
    
    Đặc điểm:
    • Syntax mirror trực tiếp vector update equations
    • 3D native (khác Manim là 2D engine có thể làm 3D)
    • Auto handle: lighting, camera navigation, perspective
    • Ideal cho: Double pendulums, orbital mechanics

PHẦN 15: CHIẾN LƯỢC TỐI ƯU RENDERING
================================================================================

[15.1] QUALITY FLAGS
    • -ql : 480p, 15fps → Development builds
    • -qh : 1080p, 60fps → High quality
    • -qk : 4K → Final "overnight" render

[15.2] PARTIAL RENDERING
    • -n 5,10 : Render animations 5 through 10 only
    • -s : Render last frame only → Instant, useful để check layout

[15.3] CACHING
    • Manim cache kết quả mỗi animation block
    • Code không đổi → Skip rendering
    • Cảnh báo: Flaky với external data files
    • Final builds: Dùng --disable_caching để đảm bảo accuracy

PHẦN 21: CÁC PHƯƠNG PHÁP ĐỊNH VỊ CƠ BẢN TRONG MANIM
================================================================================

[21.1] move_to() — ABSOLUTE POSITIONING
    Mục đích: Di chuyển object đến tọa độ chính xác (precise nhất)
    
    Cú pháp:
        square.move_to(np.array([2, 1, 0]))    # x=2, y=1, z=0
        square.move_to(UP + LEFT)               # Góc trên-trái
        square.move_to(2*RIGHT + 3*DOWN)        # 2 phải, 3 xuống
    
    Đặc điểm:
        • Dùng numpy arrays hoặc direction vectors
        • Tọa độ tuyệt đối (relative to scene center)
        • Tốt nhất cho precise placement của single elements

[21.2] next_to() — RELATIVE POSITIONING
    Mục đích: Đặt object cách object khác một khoảng (maintains relationships)
    
    Cú pháp:
        square.next_to(circle, RIGHT)              # 1 MUnit bên phải
        square.next_to(circle, RIGHT, buff=0.5)    # 0.5 MUnits cách
        triangle.next_to(circle, UP+RIGHT, buff=MED_LARGE_BUFF)
    
    Use Cases:
        • Building layouts where spacing matters
        • Consistent visual relationships
        • Arranging UI elements horizontally/vertically

[21.3] align_to() — EDGE ALIGNMENT
    Mục đích: Căn chỉnh cạnh của hai objects (critical cho professional layouts)
    
    Cú pháp:
        eq2.align_to(eq1, LEFT)     # Căn cạnh trái
        eq2.align_to(eq1, RIGHT)    # Căn cạnh phải
        eq2.align_to(eq1, UP)       # Căn cạnh trên
        eq2.align_to(eq1, DOWN)     # Căn cạnh dưới
    
    Professional Application:
        • Dùng với broken text/equations cho pixel-perfect alignment

[21.4] shift() — RELATIVE MOVEMENT
    Mục đích: Di chuyển object relative to current position
    
    Cú pháp:
        text.shift(2*UP)                           # Instant (không animate)
        self.play(ApplyMethod(text.shift, 3*DOWN)) # Animated
    
    KEY DIFFERENCE:
        • shift() alone = instant
        • ApplyMethod(obj.shift, ...) trong play() = animated

[21.5] to_edge() & to_corner() — SCREEN POSITIONING
    Mục đích: Định vị relative to screen edges và corners
    
    Cú pháp:
        title.to_edge(UP)           # Top center
        title.to_edge(DOWN)         # Bottom center
        title.to_edge(LEFT)         # Left center
        logo.to_corner(UP+LEFT)     # Top-left corner
        logo.to_corner(DOWN+RIGHT)  # Bottom-right corner
        
    Lấy tọa độ corner:
        corner_pos = title.get_corner(DOWN+RIGHT)

[35.1] THE MODULAR GRID - TOÁN HỌC CỦA LAYOUT
    
    Công thức định vị element E tại column c, row r:
    
    x_pos = M_left + c × (W_module + W_gutter)
    y_pos = M_top + r × (H_module + H_gutter)
    
    Trong đó:
    • M = margins (lề)
    • W/H = width/height
    • gutter = khoảng cách giữa các modules
    
    Ứng dụng: Tính toán precise coordinates cho grid-based layouts

[35.2] 8PT GRID - TIÊU CHUẨN DIGITAL DESIGN

PHẦN 36: GOLDEN RATIO VÀ NATURAL ORDER
================================================================================

[36.1] PHYLLOTAXIS ALGORITHM - CIRCULAR DISTRIBUTION
    
    Mục đích: Distribute icons/nodes trong circular cluster một cách đều đặn
    
    Vấn đề với approaches khác:
    • Random placement → uneven "clumping"
    • Grid approach → rectangular logic trong circular container
    
    Giải pháp - Phyllotaxis (dựa trên sunflower seeds):
    
    Công thức cho N elements, polar coordinates (r, θ) của element thứ n:
    
    θ = n × 137.5°  (The Golden Angle)
    r = c × √n
    
    Kết quả: "Perfect" packing - elements equidistant và visually balanced
    
    Coding Experience:
    • Implement bằng NumPy với vectorized operations
    • Superior hơn concentric circles (gây moire patterns)

[36.2] GESTALT PRINCIPLES TRONG CODE
    
    PROXIMITY:
    • Objects gần nhau = perceived as group
    • Manim: Dùng VGroup
    • buff giữa related items << buff giữa unrelated items
    • Ví dụ: bar-label spacing < chart-chart spacing
    
    ALIGNMENT:
    • Eye seeks continuous lines
    • "Ragged" alignment (centers aligned, edges not) = amateurish
    • Professional: "Flush" alignment với aligned_edge=LEFT
    • Tạo strong invisible vertical axis

[37.2] next_to PARADIGM - SEMANTIC RELATIONSHIPS
    
    Cơ chế next_to(target, direction, buff):

[37.3] align_to VS move_to - COMMON NOVICE MISTAKE
    
    move_to(POINT): Centers object on a point

    Coding Scenario - Table of Contents:

    ✅ GOOD:
        item1.next_to(title, DOWN, buff=LARGE_BUFF)

[38.2] OPTIMIZATION ENGINE - ensure VS encourage
    
    ensure (Hard Constraints):
    • Boolean conditions solver MUST satisfy
    • Ví dụ: ensure contains(A.shape, B.shape)
    • Guarantees "Correctness by Construction"
    • Geometry resists violation
    
    encourage (Soft Objectives):
    • Energy functions solver attempts to minimize
    • Ví dụ: encourage near(label, shape)
    • encourage disjoint(shapeA, shapeB)
    
    Professional Layout Secret:
    • encourage disjointness → system spreads elements out
    • encourage proximity → maintains readability
    • Solver balances competing forces → global optimum

[38.3] CODING EXPERIENCE - "DEFINING AXIOMS"
    
    Thay vì calculate circle distances, simply write:
    
    forall Set x; Set y
    where Intersecting(x, y) {
        ensure overlapping(x.shape, y.shape)
        encourage minimal(overlap_area(x.shape, y.shape))
    }
    
    → Solver adjusts radii và positions automatically
    → Alternative to manual "tweaking" trong Manim

PHẦN 40: "HARD PROBLEMS" CỦA ALGORITHMIC LAYOUT
================================================================================

[40.1] LABEL PLACEMENT PROBLEM
    
    Placing text labels không obscure data hoặc other labels
    → Computationally expensive (often NP-hard)
    
    SIMULATED ANNEALING (SA):
    
    Cost Function E sums penalties for:
    • Label-Label overlaps
    • Label-Data overlaps
    • Distance from anchor point
    • Ambiguous positioning
    
    Algorithm:
    1. Start với random valid placement
    2. Perturb system (move a label)
    3. Calculate ΔE
    4. If ΔE < 0 (improvement) → accept
    5. If ΔE > 0 (worse) → accept với probability P = e^(-ΔE/T)
       T = "temperature" decreases over time
    
    Why it works:
    • Probabilistic acceptance của "bad" moves
    • Escapes local minima
    • Finds cleaner global arrangement

[40.2] GREEDY "RENDER OR NUDGE" APPROACH
    
    Cho interactive/real-time visuals (faster than SA):
    
    1. Sort labels by priority (importance)
    2. Place first label at ideal spot
    3. For second label: check collision
    4. If collision → "nudge" in spiral pattern until free space found
    
    Trade-off:
    • O(N) hoặc O(N log N) vs higher complexity của SA
    • Viable cho live data
    • May result in less compact layouts

[40.3] 2D BIN PACKING - DASHBOARD LAYOUTS
    
    Arranging unequal rectangles into finite container
    
    Guillotine Packing:
    • Place rectangle into free space
    • Split remaining empty space into 2 smaller rectangles
    • Used in texture atlases, dashboards
    
    MaxRects Algorithm:
    • Maintains list of all maximal empty rectangles
    • Chooses "best" empty rectangle (Best Short Side Fit, Best Area Fit)
    
    Python: Library "rectpack" implements these heuristics
    → Mathematical efficiency, avoids "swiss cheese" gaps

[40.4] VORONOI STIPPLING - ORGANIC DISTRIBUTION
    
    Distribute elements organically but evenly
    → Avoid grid artificiality và random clumpiness
    
    Lloyd's Algorithm (Voronoi Relaxation):
    1. Generate random points
    2. Compute Voronoi Diagram (regions closest to each point)
    3. Move each point to centroid of its Voronoi region
    4. Repeat steps 2-3
    
    Result: "Blue Noise" distribution
    • Locally uniform (no two points too close)
    • Globally isotropic (no grid artifacts)
    
    Weighted Variation:
    • Weight centroid với underlying image (density map)
    • Cluster points in "dark" areas, spread in "light" areas
    • Algorithmic reconstruction of images using dots
